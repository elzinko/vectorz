**En clair.** Un jour, on renommera les skills et agents `ezk-*` en `mc-*` (pour *mega-city*),
histoire d'aligner les noms sur le produit et sur le foyer `.vectorz/mega-city/`. **Pas tout de
suite** — cette fiche capture l'intention pour ne pas la perdre. Le PO l'a demandée en
suggestion (2026-09-04).

## Contexte / Problème

Le préfixe `ezk-` est **historique**. Le produit s'appelle **mega-city** (« mc »), et on vient
de décider que le foyer mono-source des méthodes vivra dans **`.vectorz/mega-city/`**
(amendement [ADR-0048](../products/mega-city/docs/adr/0048-contenu-mono-source-modele-en-surcouche.md)).
Le décalage `ezk-*` vs `mega-city`/`mc-*` devient une petite dette de cohérence.

Ce n'est **pas urgent** : rien ne casse aujourd'hui. Mais un renommage en masse touche
**beaucoup** de fichiers (skills, agents, README, refs croisées, PLAN, fiches) — donc à faire
proprement, en une passe outillée, pas à la main.

## Proposition

Renommer l'ensemble `ezk-*` → `mc-*` (skills + agents + commandes), en s'appuyant sur
l'outillage existant plutôt qu'un sed sauvage :

- **Registre `renames.yml`** (déjà lu par lawgiver) : y déclarer chaque `ezk-x → mc-x` ; le
  re-bind **retire proprement les anciens noms** dans `~/.claude` / `.vectorz/mega-city`.
- Mettre à jour les **références croisées** (composes, rôles convoqués, docs, PLAN, help).
- Prévoir des **alias** transitoires si besoin (ne pas casser des invocations en cours).

## Critères d'acceptation

*(Provisoires — statut `idea`, à groomer le jour où on la tire.)*

- [ ] Tous les `ezk-*` (skills + agents) portent un nom `mc-*` ; `renames.yml` déclare chaque paire.
- [ ] `bind` / `bind-global` retire les anciens noms sans résidu.
- [ ] Zéro référence cassée : `pnpm test` + `test:scripts` verts, gate liens verte.
- [ ] `ezk-help` / la carte reflètent les nouveaux noms.

## Comment vérifier

```bash
cd products/mega-city && pnpm build && pnpm test && pnpm test:scripts
bash bin/test-links-repo.sh .
```
