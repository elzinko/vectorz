# 20261012231419250 — Board : la config projet

**En clair.** L'onglet « Configuration » d'un projet, en lecture claire : les défauts de lancement (grooming, taille de sprint, rétro), la qualité (release-gate, DoD), l'intégration (GitHub, racine). Il affiche aussi le **modèle par rôle**, avec le modèle **résolu** en bout de chaque ligne. Un lien renvoie à la config de l'outil.

**Si tu arrives frais.** Cette config **voyage avec le repo** (`.vectorz/config.yml`). Le *modèle par rôle* est choisi en tiers abstraits ; l'outil les résout en modèles concrets (autre tranche).

## Contexte / Problème

Tranche de la refonte dashboard. La config projet était mélangée avec la config outil ; on les sépare (ADR-074).

## Proposition

Périmètre :
- cartes Lancement / Qualité / Intégration (lecture) ;
- modèle par rôle : sélecteur de tier par rôle + modèle résolu affiché en bout de ligne ;
- lien « régler l'outil » vers la page globale.

Hors périmètre : le **mapping** tier→modèle et les défauts globaux — ils vivent dans la config outil, portée par la fiche [la page ⚙ config outil](20261013132218656_config-outil-page-reglage-mapping.md).

## Critères d'acceptation

- [ ] L'onglet config projet affiche en lecture les cartes Lancement / Qualité / Intégration, et
      **seulement** ce qui voyage avec le repo (`.vectorz/config.yml`).
- [ ] Le modèle par rôle montre un sélecteur de tier + le modèle **résolu** en bout de ligne, qui suit
      l'IDE actif.
- [ ] Un lien « régler l'outil » renvoie à la page ⚙ globale ; le mapping tier→modèle **n'est pas**
      édité ici (il vit côté outil).

## Comment vérifier

1. `pnpm --dir products/cop1/packages/web build` passe.
2. Ouvrir l'onglet config d'un projet : les cartes Lancement / Qualité / Intégration et le tier par
   rôle reprennent la maquette ; le modèle résolu s'affiche en bout de chaque ligne de rôle.
3. Changer d'IDE actif : le modèle résolu suit ; le lien « régler l'outil » ouvre la page ⚙.

Preuve : capture avant/après de l'onglet config projet.
