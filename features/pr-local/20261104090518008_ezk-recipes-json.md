# 20261104090518008 — `ezk recipes --json` publie le catalogue et les recettes d'un projet

**En clair.** `ezk recipes` montre déjà les recettes de la méthode et celles qu'un projet déclare,
mais en texte seulement. Mission control ne peut pas le lire sans recopier ou deviner. On ajoute
`--json` : la même découverte, en données, avec pour chaque recette l'endroit où elle est
implémentée.

**Si tu arrives frais.** Une recette est un pattern réutilisable documenté dans `recipes/*.md`. Un
projet « déclare » une recette en posant un `RECIPE.md` dans le dossier qui l'implémente.

## Contexte / Problème

Le PO demande le 2026-11-04 que mission control affiche « les recettes et leurs implémentations pour
chaque projet ». La règle des boards est fixée (ADR-086) : la méthode publie en JSON, mission control
consomme, jamais l'inverse. Aujourd'hui `ezk recipes --json` ignore l'option et imprime du Markdown.

## Proposition

`ezk recipes --json [--root <projet>]` imprime un objet versionné :

- `catalogue` : les recettes de la méthode, chacune avec `id`, `title`, `makes`, `status`, sa
  `source` (le chemin de l'implémentation de référence) et `incomplete` si des champs manquent ;
- `projet` : la racine lue et les recettes que ce projet déclare, chacune avec son id, son titre et
  `path`, le dossier du projet qui l'implémente.

Le cœur reste celui d'aujourd'hui (`scanDeclaredRecipes`, `renderDiscovery`) : on ajoute un rendu
JSON à côté du rendu texte. Un contrat versionné le décrit, comme `board-show`.

Une surface : la commande.

## Critères d'acceptation

- [x] `ezk recipes --json` imprime un JSON valide qui suit un schéma versionné publié sous
      `products/mega-city/contracts/recipes/v1/`.
- [x] Le catalogue contient chaque recette de `recipes/*.md`, avec son titre, ce qu'elle fabrique,
      son statut et le chemin de son implémentation de référence.
- [x] Avec `--root <projet>`, la partie projet liste les recettes déclarées par un `RECIPE.md` et le
      dossier où chacune est implémentée.
- [x] Une recette incomplète est publiée avec la liste de ses champs manquants, jamais omise.
- [x] Sans `--json`, la sortie texte ne change pas.
- [x] Les tests de la commande couvrent les deux formes.

## Comment vérifier

```bash
ezk recipes --json | jq '.catalogue | length'
bash products/mega-city/bin/test-ezk-recipes.sh   # crée un projet jetable avec un RECIPE.md : J1-J4 vérifient le JSON
pnpm --dir products/mega-city vitest run src/core/__tests__/recipe-discovery.test.ts
```
