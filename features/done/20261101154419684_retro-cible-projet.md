## En clair

Aujourd'hui, une règle sortie d'une rétro part toujours dans le catalogue de la méthode. Selon son
bundle, elle peut arriver dans tous tes projets. La rétro ne sait pas dire « ce projet seulement »,
alors que la couche existe déjà. Cette fiche ajoute la cible `projet` : la règle reste dans le
dossier `.vectorz/rules/` du projet, et la rétro dit en clair jusqu'où porte chaque règle.

## Contexte

Le 2026-11-01, le PO a demandé si une rétro s'applique seulement au projet en cours. Le constat :

- La rétro connaît trois cibles : `global`, `agent:<nom>`, `skill:<nom>`. Les trois rangent la règle
  dans le catalogue de la méthode, `products/mega-city/rules/`.
- Une règle du bundle `base` est copiée dans `~/.claude` par `ezk law bind-global`. Elle vaut donc
  pour tous les projets du poste.
- La couche « ce projet seulement » existe depuis
  [Couche de règles projet-local](../../products/mega-city/docs/adr/0050-couche-regles-projet-local.md).
  Ses règles vivent dans `.vectorz/rules/` et `ezk rules apply` les écrit dans un fichier que Claude
  ne lit que dans ce projet.
- samplerz s'en sert déjà : trois règles y ont été rangées **à la main**, à la rétro du 2026-10-03.
  Le skill de rétro, lui, n'y range jamais rien.
- Le PO avait accepté deux règles « global » sans voir que « global » voulait dire « tous tes projets ».

Conséquence : une rétro jouée dans muti, sur un souci propre à muti, rangerait sa règle dans le
catalogue de la méthode.

Le modèle voulu par le PO, trois cas :

| La règle concerne | Elle va dans | Elle vaut pour |
|---|---|---|
| la méthode (ses skills, ses agents, son socle) | le catalogue `products/mega-city/rules/` | tous les projets qui utilisent la méthode |
| vectorz, le dépôt lui-même | la couche projet de vectorz, `.vectorz/rules/` | vectorz seulement |
| le projet en cours (muti, samplerz…) | la couche projet de ce projet, `.vectorz/rules/` | ce projet seulement |

Les deux derniers cas sont le même geste : vectorz est un projet comme les autres pour sa couche
projet. Il héberge en plus le catalogue de la méthode.

## Proposition

1. Le validateur de capture accepte la cible `projet`.
2. Le skill `ezk-retro` décrit la cible `projet` :
   - hors du dépôt de la méthode, c'est la cible par défaut d'une règle ;
   - la règle va dans `.vectorz/rules/<id>.md`, le manifeste `.vectorz/rules.yml` est créé s'il
     manque, un MUST y reçoit son binding, puis `ezk rules check` et `ezk rules apply` ;
   - pas de bundle, pas de compteur `expand.test.ts` ;
   - `retire` sait retirer une règle de projet.
3. Quand la rétro présente une règle au PO, elle dit sa portée en mots : « ce projet seulement »,
   « tous tes projets », « partout où <skill ou agent> tourne ».
4. Le gabarit de capture liste la cible `projet` et sa portée.

## Critères d'acceptation

- [ ] `ezk retro captures --check` accepte une règle `target: projet`, et refuse toujours une cible inconnue.
- [ ] Le message d'erreur sur une cible manquante ou fausse cite `projet`.
- [ ] Le skill nomme la cible `projet`, le dossier `.vectorz/rules/` et `ezk rules apply`.
- [ ] Le skill dit que `projet` est la cible par défaut hors du dépôt de la méthode.
- [ ] Le skill exige de dire la portée de chaque règle en mots, au moment où le PO tranche.
- [ ] Le gabarit de capture liste `projet` parmi les cibles.

## Comment vérifier

```bash
pnpm --dir products/mega-city exec vitest run src/core/__tests__/retro-capture.test.ts src/__tests__/ezk-retro-capture-contract.test.ts
```

Signal observable : une capture dont une règle porte `target: projet` passe `ezk retro captures --check`.

## Notes

- Hors scope : migrer des règles existantes du catalogue vers un projet. Aucune ne vient d'un projet hôte.
- Hors scope : ranger depuis un projet hôte une règle `global` dans le catalogue de vectorz. La
  rétro le signale en clair ; le geste reste à la main, comme aujourd'hui.
- Hors scope : le nom du dossier `.vectorz/`. Le PO le trouve trompeur, puisque ce dossier est le
  contrat du projet avec la méthode. Le renommer touche quatre projets et le code : c'est une fiche
  à part.
