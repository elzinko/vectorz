# 20260828165644386 — Vue « écart plan » (ce qui a bougé depuis le plan)

## En clair

La vue « Plan » (livrée, PR #169) montre l'**ordre décidé** du travail. Elle ne montre **pas
ce qui a bougé depuis**. Quand on ajoute des fiches après avoir décidé un plan, elles restent
**invisibles**, et on pilote sur une photo périmée.

Cette fiche ajoute, dans l'onglet Plan, un **encart « ce qui a bougé »** : les **N dernières
fiches créées**, chacune marquée **« dans le plan »** ou **« hors plan »**. Plus un **compteur**
« X fiches actives hors plan » pour l'ampleur.

Pourquoi pas simplement « toutes les fiches hors plan » : ça ferait un **mur de ~90 lignes**
(dont 81 idées). On vise le signal utile — les **nouveautés**, et lesquelles ne sont **pas
encore planifiées**.

Bonne surprise : **pas besoin de dater le plan**. Les ids de fiche **sont** des dates de
création ; « les N dernières » se calcule en triant les ids. Le delta se dérive de l'existant.

## Contexte / Problème

`PLAN.md` est curé à la main et **n'a pas de date de génération** propre (les dates y sont en
prose, éparses : « réaligné le 2026-08-26 », « décidé le 2026-07-26 »). Le backlog, lui,
s'enrichit en continu. Chiffres réels du 2026-08-28 : 263 fiches, **81 idées**, 53 todo (2
ready). Une liste « hors plan » brute = ~90 lignes, noyée par les idées → inutilisable.

Besoin PO (2026-08-28) : voir **les dernières features arrivées** et **lesquelles ne sont pas
dans le plan**, pour décider de les planifier.

Fondations présentes (vérifiées le 2026-08-28) : `parsePlanSections`
(`src/backlog/plan-sections.ts`, capte **tous** les ids d'une ligne), `loadFiches` (le
front-matter, dont l'id = date de création), `buildPlanViewData` (`src/core/plan-view-data.ts`,
le patron à imiter), l'onglet Plan (`diagrams/avancement/board.html`).

## Proposition

POC d'abord, dans l'onglet **Plan** existant (pas de page séparée).

1. **Un cœur pur** `plan-delta-data.ts` (patron `plan-view-data.ts`) :
   `buildPlanDelta(planMd, fiches, n)` — tout injecté, aucun `fs`.
   - **Ensemble « dans le plan »** = **tous** les ids cités par `parsePlanSections(planMd)`
     (et **pas** `parsePlanOrder`, qui ne garde que le 1er id d'une ligne — sinon une fiche
     citée en 2ᵉ position d'une ligne multi-ids serait « hors plan » à tort).
   - **Dernières créées** = les **N fiches actives d'id le plus grand** (id = horodatage de
     création), N réglable (défaut **15**). Chacune porte un booléen `dansLePlan`.
   - **Compteur hors-plan** = nombre de fiches **actives hors idées** (todo + in-progress +
     blocked) dont l'id n'est **pas** dans l'ensemble du plan. Les **idées sont exclues**.
2. **Un encart « ce qui a bougé »** en tête de l'onglet Plan : la liste des N dernières (id,
   titre, statut, priorité, **badge dans/hors plan**, cliquable vers la fiche) + la ligne
   « hors plan : X ». Dérouler la liste hors-plan complète = **hors MVP**.
3. **Compilé, jamais saisi** : bord `regen-plan-delta.ts` (marqueurs disjoints de ceux
   d'avancement et de plan-view), **test d'invariant** qui rougit si `PLAN.md` / backlog
   changent sans regen, rendu `textContent`.

## Critères d'acceptation

- [ ] L'onglet Plan affiche un encart listant les **N dernières fiches créées** (défaut 15),
      de la plus récente à la plus ancienne (tri par id).
- [ ] Chaque ligne porte un **badge « dans le plan » / « hors plan »**, l'id, le titre, le
      statut, la priorité, et **cliquer ouvre la fiche**.
- [ ] **« Dans le plan » est vrai si l'id apparaît n'importe où dans `PLAN.md`** — y compris en
      2ᵉ+ position d'une ligne multi-ids. Test dédié sur une ligne type
      « Distribution — 0087 · 0050 · 0096 · 0186 ».
- [ ] Un **compteur « hors plan : X »** compte les fiches actives **hors idées**
      (todo / in-progress / blocked) absentes du plan ; les idées ne comptent pas.
- [ ] **N est une constante réglable** ; le rendu reste correct si le backlog a moins de N
      fiches.
- [ ] Delta **calculé** (cœur pur + regen + test d'invariant) — aucun nouveau champ sur les
      fiches, aucun objet « plan versionné », aucune saisie à la main.
- [ ] Rendu par `textContent` (anti-XSS) ; parité dark mode avec le board.
- [ ] Gate locale verte (typecheck / lint / tests) ; liens markdown OK.

## Comment vérifier

```bash
pnpm --dir products/mega-city test               # cœur pur + invariant (dont ligne multi-ids)
pnpm --dir products/mega-city plan-delta:regen   # (nouveau bord I/O)
pnpm ezk:map avancement                          # onglet Plan → encart « ce qui a bougé »
```

Preuve agent attendue : capture de l'encart (N dernières badgées dans/hors plan + compteur
« hors plan : X ») sur le backlog réel, et les tests d'invariant verts.

## Notes / décisions

- **Origine** : brainstorm PO 2026-08-28 (vue de pilotage). **Groomée le 2026-08-28.**
- **Grooming (décisions PO)** : signal = « N dernières créées + badge dans/hors plan » (pas la
  grande liste hors-plan, qui ferait ~90 lignes) ; fenêtre = **N dernières par id** (pas de date
  de plan) ; **idées exclues** du compteur hors-plan.
- **Justesse technique** : présence dans le plan = union de **tous** les ids via
  `parsePlanSections`, pas `parsePlanOrder`.
- **Écartés pour le MVP** (évolutions si le besoin se confirme) : une ligne « Plan arrêté
  le … » à maintenir en tête de `PLAN.md` ; le déroulé complet de la liste hors-plan.
- Suite scopée de la vue Plan livrée [[20260825213807501]] (PR #169). Même famille « pilotage »
  que [[20260825141012293]].
- **Ne rouvre pas** la frise / sprint-as-data (gelée, verdict panel 2026-08-23).
