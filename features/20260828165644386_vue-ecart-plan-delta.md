# 20260828165644386 — Vue « écart plan » (delta plan ↔ backlog)

## En clair

La vue « Plan » (livrée, PR #169) montre l'**ordre décidé** du travail — le contenu de
`PLAN.md`. Elle ne montre **pas ce qui a bougé depuis**. Quand on ajoute des fiches après
avoir décidé un plan, elles restent **invisibles** dans le plan, et on pilote sur une photo
périmée.

Cette fiche ajoute **deux signaux** à côté du plan :

1. **Hors plan** — les fiches actives (todo / in-progress / blocked) qui **n'apparaissent
   pas** dans `PLAN.md`.
2. **Ajoutées depuis** — les fiches **créées après la dernière décision de plan** (leur
   id-horodaté est postérieur à la date du plan).

Bonne surprise : **pas besoin de versionner le plan**. Les ids de fiche **sont** des dates de
création, et `PLAN.md` est daté. Le delta se **calcule** depuis l'existant.

## Contexte / Problème

`PLAN.md` est curé à la main par le PO (sections datées « décidé le AAAA-MM-JJ »). Le backlog,
lui, s'enrichit en continu (chaque session ajoute des fiches). Rien ne montre l'**écart** entre
les deux : quelles fiches neuves ne sont pas encore rangées dans le plan, et lesquelles sont
arrivées après la dernière décision. Demande PO (2026-08-28) : voir cet écart pour re-planifier
au bon moment.

Fondations déjà là (vue Plan, `20260825213807501`) : `parsePlanOrder` (les ids cités par
`PLAN.md`), `loadFiches` (tout le front-matter, dont l'id = date de création), le patron
« cœur pur + bord regen + test d'invariant ».

## Proposition

POC d'abord, dans l'onglet **Plan** existant du board (ne pas créer de page séparée).

1. **Un cœur pur** `plan-delta-data.ts` (patron `plan-view-data.ts`) :
   `buildPlanDelta(planMd, fiches)` — tout injecté, aucun `fs`.
   - **Hors plan** = ids des fiches actives ∖ ids cités par `parsePlanOrder(planMd)`.
     (Choix à trancher au grooming : inclure ou non les `idea` — a priori **non**, elles ne
     sont pas encore dans le flux.)
   - **Ajoutées depuis** = fiches dont l'id-horodaté > **date de référence du plan**.
     (Choix à trancher : date globale en tête de `PLAN.md`, ou la plus récente des sections.)
2. **Un encart « écart » dans l'onglet Plan** : deux petites listes cliquables (hors plan /
   ajoutées depuis), chacune avec son compte. Vide = état clair « plan à jour ».
3. **Compilé, jamais saisi** : bord `regen-plan-delta.ts` (marqueurs disjoints), **test
   d'invariant** qui rougit si `PLAN.md` / backlog changent sans regen. Rendu `textContent`.

## Critères d'acceptation

- [ ] L'onglet Plan affiche une liste **« hors plan »** : les fiches actives absentes de
      `PLAN.md`, chacune cliquable vers sa fiche, avec le compte.
- [ ] L'onglet Plan affiche une liste **« ajoutées depuis le plan »** : les fiches créées
      après la date de référence du plan, avec le compte.
- [ ] Le delta est **calculé** (cœur pur + regen + test d'invariant) — aucune saisie à la
      main, aucun nouveau champ sur les fiches, aucun objet « plan versionné ».
- [ ] Les listes vides affichent un **état clair** (« plan à jour »), jamais un bloc cassé.
- [ ] Rendu par `textContent` (anti-XSS), parité dark mode avec le board.
- [ ] Gate locale verte (typecheck / lint / tests) ; liens markdown OK.

## Comment vérifier

```bash
pnpm --dir products/mega-city test               # cœur pur + invariant
pnpm --dir products/mega-city plan-delta:regen   # (nouveau bord I/O)
pnpm ezk:map avancement                          # onglet Plan → encart « écart »
```

Preuve agent attendue : capture de l'onglet Plan montrant les deux listes (hors plan / ajoutées
depuis) sur le backlog réel, et les tests d'invariant verts.
