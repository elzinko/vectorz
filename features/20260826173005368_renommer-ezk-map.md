# 20260826173005368 — Renommer ezk:map (le site de monitoring de la méthode)

## En clair

`ezk:map` ne fait plus ce que son nom dit. Au départ, c'était la **carte des skills**.
Aujourd'hui, c'est le **tableau de bord** de la méthode mega-city : board kanban, plan,
avancement des sprints, cartes, et bientôt l'onglet sessions. Le mot « map » induit en
erreur — un nouvel arrivant croit à une simple carte. On renomme la commande et le
composant pour qu'ils disent ce que c'est.

## Contexte / Problème

- La commande `pnpm ezk:map` démarre un petit serveur local (`products/mega-city/bin/ezk-map.ts`)
  qui sert, sous une page d'accueil à onglets : la carte de la méthode, le **board** (20260825213807501),
  la vue **Plan**, la vue **d'avancement** (20260823124042842), un **menu de cartes** et une
  **navigation** entre elles (20260825152954193, 20260825232147620), et bientôt le **cockpit de
  sessions** (20260825141012293).
- Le nom `map` date de l'époque « une seule carte des skills ». Il ne couvre plus le périmètre.
  Dans `ezk-help`, la doc et les `SKILL.md`, `ezk:map` est encore présenté comme la visionneuse de
  diagrammes — ce n'est plus vrai.
- Conséquence : le composant central de monitoring de la méthode est **mal nommé, donc mal
  découvert**.

## Proposition

1. **Choisir un nom qui dit « tableau de bord / monitoring de la méthode ».** Pistes (tranchées au
   grooming, éventuellement via `product-brainstorming`) collant à la métaphore *mega-city* :
   `ezk:city`, `ezk:hq`, `ezk:monitor`, `ezk:board`, `ezk:dash`. Garder le préfixe `ezk:`.
2. **Renommer la commande et le fichier** : clé de script dans `products/mega-city/package.json`,
   `bin/ezk-map.ts`, la variable d'env `EZK_MAP_PORT`, et **toutes** les références (`ezk-help`, les
   `SKILL.md`, la doc, les diagrammes).
3. **Garder un alias `ezk:map` de dépréciation** qui délègue au nouveau nom (avec avertissement),
   pour ne pas casser les sessions et docs en cours. Son retrait est tracé dans une fiche de suivi.
4. **Afficher l'état d'installation dans le site** (l'ajout demandé) : une section qui montre, pour
   le projet courant, la **version de méthode installée** et les **migrations en attente** (source :
   le registre de bind + `skema status` de [0186](0186-skema-versioning-migrations-skills-deployees.md)).
   C'est le lien naturel entre « site de monitoring » et « infos d'installation ».
   **Incrément séparable** : cette partie dépend du registre de bind (0186) ; le rename pur peut
   livrer **seul**, l'affichage d'install suit quand le registre existe.

## Critères d'acceptation

- [ ] Un **nom cible** est décidé et acté (le grooming tranche parmi les pistes).
- [ ] `pnpm <nouveau-nom>` démarre le serveur comme avant ; **toutes les vues** fonctionnent.
- [ ] `package.json`, `bin/`, l'env, `ezk-help`, les `SKILL.md` et la doc référencent le **nouveau
      nom** ; plus aucune référence morte à `ezk:map` (hors alias de dépréciation assumé).
- [ ] Un **alias `ezk:map`** continue de marcher (avec avertissement), OU son retrait est tracé
      dans une fiche de suivi.
- [ ] *(Séparable)* Le site montre l'**état d'installation** du projet courant (version méthode +
      migrations en attente), ou un état dégradé propre si le registre 0186 n'existe pas encore.
- [ ] `ezk-help` régénéré ; **liens vérifiés** (pas de lien cassé introduit par le rename).
- [ ] Gate locale verte (build / test / lint).

## Comment vérifier

```bash
# le nouveau nom démarre le site, toutes les vues répondent
pnpm --dir products/mega-city <nouveau-nom>
# aucune référence morte au vieux nom (hors alias de dépréciation)
grep -rn "ezk:map" products/mega-city skills docs
```

Attendu : le serveur démarre, la page d'accueil liste les onglets, l'onglet d'installation affiche
version + migrations en attente (si 0186 est là) ; le `grep` ne remonte que l'alias de dépréciation.

## Notes / décisions

- **Vigilance rename en masse** (déjà vécu) : un renommage global **corrompt les textes qui
  comparent deux noms** (fiches/docs qui décrivent « avant `ezk:map` → après ») et une **liste
  blanche d'extensions rate `.html` / `.mmd` / `.svg`** en silence. Traiter le rename par type de
  fichier, vérifier les diagrammes rendus.
- **Périmètre = nommage + repositionnement**, pas de refonte des vues (elles existent déjà). Petite
  touche archi : acter que ce composant **EST** le site de monitoring de la méthode (son identité),
  pas une visionneuse de diagrammes.
- **Préférence PO (2026-08-26)** : candidats de tête = **`ezk:monitor`** (préféré) et **`ezk:board`**.
  ⚠️ Réserve sur `ezk:monitor` : **ne pas confondre** avec l'app qui monitore les events (le Moniteur
  de supervision / mission-control) — à trancher au grooming, avec l'« urbanisation » des noms de
  commandes (différée).
- Nom définitif à acter au grooming (`product-brainstorming` / `engineering:architecture`).
