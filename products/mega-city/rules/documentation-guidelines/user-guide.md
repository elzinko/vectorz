---
id: documentation-guidelines/user-guide
kind: disposition
level: SHOULD
title: Separate User Guide
---

- Create docs/GUIDE.md for detailed usage documentation
- Include: installation options, all commands, configuration, examples
- Target audience: users who install the package
- Keep separate from contributor documentation
- Write in PM/writer voice for the ACTUAL target reader (benefit first, plain
  language, jargon defined at first use) — an integrator reference is NOT a user guide
- Before publishing a user-facing doc, run an adversarial review with ≥3 reader
  personas, including ≥1 persona that actually EXECUTES the instructions
  (retro 2026-07-18: that reviewer caught 3 blocking config bugs)
