Panel demandé par le PO avant de coder. Trois relecteurs indépendants sur la décision
« installer ezk dans Cursor + modèles par hôte + contenu mono-source ». Fiche
[`20260901173549334`](../../../../features/20260901173549334_ezk-multi-client-cursor-modeles-par-hote.md).

## Verdicts

| Relecteur | Verdict | Message |
|---|---|---|
| Architecte (solidité/YAGNI) | **GO-avec-amendements** | Direction saine, deux frontières à fixer + POC sur-outillé |

Mais recadrer, trancher l'interop, et **vérifier dans un vrai Cursor** avant de coder le modèle.

## Findings retenus (convergents)

1. **Sur-cadrage (3/3).** Presets `econome/equilibre/max`, manifeste, flag `--models`, routeur
   partagé = « au cas où » (à moitié pour cop1, hors périmètre). → **un seul `models.cursor.yml`**
   lu au bind, écrit en dur dans le subagent. Le reste est réintroductible plus tard sans rien casser.

2. **La table modèle est morte pour Claude en mode lien (architecte F1, reviewer P1).** `--link`
   symlinke la source verbatim ; le modèle vient de la frontmatter, pas d'un yaml. `models.claude-code.yml`
   serait décoratif. → **v1 : table Cursor-only.** Claude garde frontmatter + lien comme unique
   vérité (= la config du PO, préservée). Lève la contradiction 0047 D2 ↔ 0048 D3.

3. **Le modèle Cursor repose sur du supposé (reviewer P0, PM #5).** Slug exact d'Opus 4.8 +
   syntaxe `[effort=high]` non vérifiés. Slug faux → **repli silencieux** sur le modèle par défaut
   de Cursor, sans erreur, non testable → contrôle de coût illusoire. → **POC empirique** dans un
   vrai Cursor AVANT de coder la brique 2 ; test qui échoue si le slug n'est pas dans une liste
   blanche vérifiée.

## Blocage n°1 — interop `.claude/agents` (reviewer P0, architecte F5)

Cursor lit **aussi** `.claude/agents/`. Agents Claude liés (`claude-opus-4-8` + `effort:` en clés
séparées) réapparaissent dans Cursor à côté des `.cursor/agents/` générés → bug de départ +
collision de noms (`name` identique). Le critère « grep claude-opus-4-8 dans la sortie Cursor »
ne voit pas cette fuite. **À trancher avant même la brique 1** : isoler l'install Cursor, ou
décider la précédence, ou ne pas poser les agents Claude dans un projet Cursor.

## Corrections techniques retenues

- **`agentContent` n'est pas host-agnostique (reviewer P1, architecte F3).** Il émet
  `model_spare`/`effort`/`isolation` en clés séparées ; Cursor veut l'effort **plié** dans le
  modèle et n'a que name/description/model/readonly/is_background. → `agentContent(agent, resolved, host)`
  avec branche Cursor. **Structurel, pas « mineur ».**
- **Frontière du résolveur (architecte F2/F3).** Fonction **pure** `resolve(table, host, agentId)
  → {model, effort}` ; table **chargée par le loader** (I/O), passée en donnée à `bind` (cœur pur,
  ADR-0003) ; `bind` réécrit `{model, effort}` par hôte **avant** les caps ; les caps ne font que
  **rendre**. Le résolveur émet un tuple neutre, ignore la syntaxe des crochets.
- **IO global couplé au layout Claude (reviewer P1).** `applyGlobalPlan` ne matérialise que
  `skills/` et `agents/` → `.cursor/rules/*.mdc` passerait à la trappe. Rendre l'IO global
  host-aware, ou router le cap Cursor via `applyPlan`.
- **Distribution vs skills liées (reviewer P1).** Les liens pointent en dur vers le checkout de
  l'auteur → cassés ailleurs. OK en perso ; noter que « zéro copie via lien » et la distribution
  (0087) sont incompatibles → mode `copy` pour l'axe distribution.
- **Symlink de skill non prouvé (reviewer P1).** Cursor suit-il un dossier skill lié ? À prouver
  au POC, sinon copier.
- **Staleness (reviewer P2).** Sortie Cursor générée périmée après édition du rôle jusqu'au
  re-bind. Estampiller la sortie avec un hash de la source + gate qui signale le périmé.
- **`isolation: worktree` (reviewer P2).** N'existe pas côté Cursor ; comportement divergent à documenter.

## Décision du PO (2026-09-03)

- **Recadrage ratifié** : un seul `models.cursor.yml`, table **Cursor-only**, on parque
  presets/manifeste/flag/routeur (réversible).
- **Prochain pas = POC empirique Cursor** (les 4 questions : modèle honoré, slug exact, interop,
  symlink suivi), pas de code à l'aveugle, pas de 2ᵉ panel.
- Amendements ci-dessus portés aux ADR-0047/0048.

Aucun REFUS déclenché (rien d'irréversible/sortant, pas d'augmentation de budget, pas de
contradiction de LOI) — recadrage décidable au niveau PO.

## POC empirique — résultats (2026-09-03)

Joué dans un vrai Cursor (`~/ezk-cursor-poc`). Détail :
[spike § POC](../spikes/2026-09-03-cursor-cap-format.md).

- **Modèle par agent HONORÉ** avec le slug Cursor exact `claude-opus-4-8-thinking-high` (effort
  **dans le nom**). `claude-opus-4-8[effort=high]` → **repli silencieux** sur le parent. ⇒ le P0
  « slug » du reviewer est réel ; on l'adresse par une **liste blanche** de slugs + build qui
  **échoue** hors liste. Le résolveur Cursor émet **un slug** (modèle+effort fondus), pas un tuple.
- **Interop `.claude/agents` RÉELLE** (P0 reviewer confirmé) : les deux dossiers sont listés ; ezk
  étant global dans `~/.claude`, Cursor les voit partout → **à trancher** (précédence de l'install
  Cursor). Reste le seul point de conception ouvert.
- **Symlink de skill SUIVI** ⇒ **skills liées = zéro copie**, validé (Q4 du panel).
