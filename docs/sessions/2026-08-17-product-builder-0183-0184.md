### En clair (décision 0191 × ADR-0029)

**En clair.** ADR-0029 a déjà réglé la moitié de 0191 : le corps de PR n'est plus un texte à part, c'est le **rendu de la fiche**, et le gabarit atteint bien le moment où on écrit. Ce qui manque encore, c'est exactement ce qui avait rendu la PR #125 opaque : **le vocabulaire pour un nouveau + un glossaire**, et une **vérif qui attrape un corps opaque** au sens (pas juste sa structure). On construit ce résidu mince — dans le **template de fiche** (que la PR rend), jamais dans un template de PR parallèle — puis on ferme.

**Réf. :** fiche `features/0191-lisibilite-templates-llm-au-moment-genere.md` (ready 2026-08-14) ; ADR-0029 (accepté 2026-08-16, #152).

#### 1. AC déjà livrés par ADR-0029 / #152 (analyse confirmée)

- **AC1 « template PR séparé » : OBSOLÈTE tel quel.** ADR-0029 interdit un corps de PR rédigé à côté : le corps **rend** la fiche. Interdit de réintroduire un `PULL_REQUEST_TEMPLATE` parallèle ou un `## Summary`. → Seule survit la **substance** (vocabulaire nouveau + glossaire), à porter dans le **template de fiche**.
- **AC2 « atteindre le moment de la génération » : LARGEMENT LIVRÉ.** Gabarit inliné dans `ezk-pr-pilot` (+ fallback copy-mode) et étape PR d'`ezk-sprint` = « rendre la fiche ». Résidu = y répercuter les nouvelles sections (point 2 ci-dessous).
- **AC3 « catch un corps opaque » : STRUCTUREL LIVRÉ, SÉMANTIQUE MANQUANT.** `check-pr-body.sh` + `human-facing-lisibility-contract.test.ts` gardent la structure (En clair, provenance, `## Comment vérifier`, matrice) ; **aucune** lentille « nouveau venu » n'opérationnalise la mesure 3/3, ni de contrôle « glossaire présent si jargon ».
- **AC4 (BMAD) / AC5 (article) : DÉPORTÉS** en filles (inchangé).

#### 2. Périmètre MVP résiduel à construire (précis, testable, STRICTEMENT ADR-0029)

- **R1 — Template de fiche (rendu par la PR, PAS de template PR parallèle).** `ezk-backlog/templates/feature-template.md` gagne : (a) une ouverture **« Si tu arrives frais »** (vocabulaire projet, ≤ 2 lignes) et (b) une section **`## Glossaire`** — **conditionnelle : exigée dès qu'il y a du jargon interne** (évite d'alourdir les micro-fiches, et lève la tension avec `human-facing-lisibility` qui garde le jargon hors ouverture). Testable : les sections existent dans le template ; le contrat triade les référence.
- **R2 — Renfort au moment d'écrire (AC2 résiduel).** La consigne de rendu inlinée (`ezk-sprint` étape PR + `ezk-pr-pilot`) exige explicitement de rendre « Si tu arrives frais » + `## Glossaire` quand la fiche les porte. Testable : la consigne inlinée cite les deux sections.
- **R3 — Vérif du corps (AC3), 2 étages :** (a) **garde structurelle déterministe** — `check-pr-body.sh` / contrat : « `## Glossaire` présent si jargon détecté » ; (b) **lentille sémantique** — voir verdict AC3 ci-dessous.
- **Hors scope (garde-fou ADR-0029) :** aucun corps de PR rédigé hors fiche ; aucun `## Summary` ; sur divergence la fiche gagne.

#### 3. Verdict AC3 — **lentille reviewer dédiée** (+ garde structurelle mince)

La mesure « un tiers reformule le besoin en 1 phrase (3/3 sur 3 PR) » est un **jugement sémantique** qu'un test de contrat déterministe **ne peut pas** rendre (il ne sait pas dire si une prose par ailleurs complète est opaque). → **AC3 = lentille `ezk-reviewer` dédiée « nouveau venu »** sur la prose du corps, opérationnalisant le 3/3 ; **complétée** par la garde structurelle « glossaire si jargon » (R3-a) pour la part réellement mécanisable. **Pas de renvoi bloquant à `ezk-architect`** : la réponse est tranchée. *Option non bloquante :* si le product-builder veut figer la frontière lentille-reviewer ↔ `agent-check` dans un ADR court, il peut demander **UN** avis `ezk-architect` — recommandé, non requis.

#### 4. Filles à créer au build (confirmé déporté)

- **AC4 → fille** : « Étude prior-art BMAD (templates + elicitation) → ce qui se transpose à une méthode LLM-native » (note transposable/non-transposable ; réf. 0049/0162).
- **AC5 → fille** : « Article “Templates de réponse adaptés aux LLM” via `ezk-article` » (persona = dev/PM qui arrive sur un projet).

#### 5. Verdict sprint — **BUILD** (résidu mince, 1 PR squash, cap tokens)

0191 n'est **pas** substantiellement livré : le cœur de valeur (onboarding vocab + glossaire + catch d'opacité sémantique) = précisément le trou de la PR #125 qui a motivé la fiche, et il reste ouvert. Résidu cohérent et resserré (R1+R2+R3) → **un** sprint, gate hôte `pnpm build+test+lint` (act/Docker inutilisables ici). **Réversibilité :** si la lentille reviewer se révèle trop coûteuse/bruyante sur la fenêtre des 3 PR de mesure, dégrader vers la garde structurelle seule (R3-a) et rouvrir une fille « lentille sémantique ».
