Trois étages. Le moteur (règles · bundles · profils · bind) ne connaît pas scrum — il compose et matérialise. La méthode (cérémonies, rôles, artefacts) est une instance construite avec lui. Les modules (GitHub, sessions LLM, supervision, outillage, overlays) s'y activent sans en faire partie. Cette carte n'est pas dessinée à la main : tout est compilé depuis les fichiers du dépôt. Le cycle d'une feature — inspiré de Scrum

Comment une idée devient du code mergé

Cinq temps. Dans chaque temps : l'étape (la cérémonie qui la porte) et les acteurs (les juges convoqués). Les cartes citées sont réelles : cliquez-les.

À part du cycle : la clôture de session (ezk-archive) n'est pas un rituel scrum — c'est l'hygiène de l'hôte LLM, jouée à chaque fin de session, où qu'on soit dans le cycle.

Honnêteté du vocabulaire (panel adverse du 2026-08-23) : ≈ = adapté de Scrum, ≠ = faux ami. Le « sprint » maison est un run mono-fiche sans timebox, le Daily Scrum n'a pas d'équivalent, et « Toi » (le PO humain) n'existe pas comme objet du modèle — les chips en pointillé sont éditoriales, pas compilées.

Les modules — hors méthode, activables

Ce que la méthode active sans en faire partie

Cinq familles : hôte LLM (sessions), GitHub (revue Codex), observabilité (supervision), techno (outillage qui ignore tout du scrum), et les overlays (la surcharge déclarative, ADR-0039) — vz-product-builder est le premier. La famille est sur chaque carte. « Modules » : le mot de BMAD pour les composants activables (PO 2026-08-24).

Ce qui fabrique et garde le catalogue

La méta-couche : ezk-ezk crée les skills et son audit convoque ezk-steward, le gardien. Hors méthode, hors modules — c'est l'atelier.

La loi

Les règles, rangées par bundle

Une règle = une contrainte de travail (MUST / SHOULD / MAY). Un bundle = un paquet de règles qu'un profil embarque d'un bloc. Les règles ne s'accrochent pas aux commandes : elles arrivent par les profils (bundles) et par les juges (interactions).

Le keystone

Profils — le bon de commande d'un projet

Un profil dit : « ce projet travaille avec ces règles (bundles), ces juges (agents) et ces commandes (skills) ». Ensuite bind lit ce bon de commande et écrit les fichiers chez l'hôte (~/.claude/…) — c'est le moule caps/<host>.
